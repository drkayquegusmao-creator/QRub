# AJUSTES Module Implementation Plan

## Goal
Create a comprehensive **AJUSTES** module for QRub that provides user settings, permission‑based admin panels, anti‑white‑screen handling, and persistence via Supabase with local caching.

## High‑Level Architecture
- **Frontend**: Next.js (App Router) + React + Tailwind CSS (custom config). All UI follows the app’s purple‑ban, bold geometry, and animated micro‑interactions.
- **Backend**: Supabase tables + Row‑Level Security (RLS) policies. Server‑side API routes for CRUD of settings, user profile, feature flags, and audit logs.
- **State**: React Query (TanStack Query) for data fetching & caching, with fallback to `localStorage` for instant UI response.
- **Auth**: Supabase auth session, bearer token passed in API calls.
- **Permissions**: Computed on client (`permissionService`) and enforced on server via RLS.

## Acceptance Criteria
- Users see **AJUSTES** modal with correct cards based on their role.
- All settings changes are saved instantly locally and persisted to Supabase.
- Admin users see **Painel Admin** card; Master sees additional admin cards.
- No white screen: loading skeletons appear instantly; error states are user‑friendly.
- All actions performed by `ADMIN_MASTER` generate an entry in `audit_logs`.
- UI follows the app’s design language: no purple, sharp geometry, animated micro‑interactions, layered depth.
- Lint, TypeScript, and tests all pass.
